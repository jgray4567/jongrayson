## Cracked Sky Band Site — Show Events Bug (CRITICAL DEBUG)

**Problem:** Events/shows not displaying on mobile phones (Safari + Chrome, two different phones). OHM worked fine. Headless browser showed events loading correctly — very misleading.

**Root cause:** CSS `.reveal` class sets `opacity: 0`. Events need `.reveal.visible` to become visible (`opacity: 1`, `transform: none`). The inline script created cards with `className: 'show-row reveal active'` but never added the `visible` class. The `active` class has no CSS effect on visibility. The IntersectionObserver that adds `.visible` only watches elements present at page load — dynamically added elements are never observed.

**Fix:** Added `.classList.add('visible')` to each dynamically created show card in the inline script. Also called `initReveal()` from `main.js` as a fallback to re-observe new elements.

**Key lesson:** Headless browser testing can miss CSS visibility issues. The DOM was correct (elements existed) but they were invisible (`opacity: 0`). Always check both DOM presence AND computed styles.

**Debugging path taken (expensive):**
1. First thought it was CORS — fixed `window.location.origin` 
2. Then thought it was browser caching — added cache-bust params, private tabs
3. Then thought `main.js` was crashing and blocking `events.js` — inlined the script
4. Then thought CDN cache — deployed multiple times
5. Finally found the real issue: CSS visibility class not being added

**Lesson:** When DOM is correct but user sees "nothing", check `opacity`, `visibility`, `display`, and `height: 0` — not just JS logic.
