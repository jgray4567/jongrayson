## OpenMythos Deep Assessment (YouTube + Article)

Jon shared: https://youtu.be/k68Dodj3vwA — "OpenMythos Is INSANE!"

### Key Takeaways from the Ecosystem Coverage:

**Architecture hypothesis:** Mythos = Recurrent-Depth Transformer + MoE + MLA
- Looped block runs up to 16 times per forward pass
- Reasoning in continuous latent space (not token CoT)
- MoE supplies domain breadth, loops supply reasoning depth
- MLA (DeepSeek-V2 style) cuts KV cache 10-20x vs standard attention

**Why it matters for Jerry/T&T:**
1. **Inference-time scaling** — same model, variable compute. Easy tokens exit early (ACT halting), hard tokens get more loops. Perfect for recipe API where some URLs are simple and others need deep reasoning.
2. **Parameter efficiency** — 770M RDT matches 1.3B standard transformer (Parcae/Prairie 2026). Means Jerry could run a smaller model that punches above its weight.
3. **Per-token cost flexibility** — "pay more for harder questions, less for easy ones" — ideal for serving both free and premium T&T users.
4. **Memory efficiency** — MLA + MoE means production KV cache is much smaller. On M4 Max 128GB, could serve way more concurrent users.

**Credibility assessment:**
- NOT a leak — one developer's well-informed guess
- Kye Gomez (swarms framework author) — real adoption but mixed reputation for attribution
- Code compiles and runs today (we've cloned it)
- Built on solid published research: DeepSeek-V2, COCONUT, Saunshi et al.
- The falsifiable hypothesis: if Anthropic eventually confirms RDT+MoE+MLA, OpenMythos was right

**Risk:** If Mythos is actually a dense transformer with different test-time compute, this is an instructive exercise with a misleading name. Either way, the code is useful as a reference implementation.

**Bottom line for Jerry:** OpenMythos gives us a concrete, runnable architecture to experiment with for the Jerry inference server. Even if the Mythos label doesn't hold, the RDT+MoE+MLA combination is a legitimate post-dense-transformer production architecture worth exploring.

  - Simple requests (URL parse): 2-4 loops, <2s
