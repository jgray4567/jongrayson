# 2026-04-14

- Jon set a UI guideline for command-surface design: quantitative status can act as the control. Example standard: “(Number) Systems Online” where the live number itself is clickable and opens the modal used to activate or deactivate items.
- Preferred interaction model: calm default surface, activation-driven reveal, and live counts as buttons instead of generic configure controls when the count represents the thing being configured.
- Jon wants the `jongrayson/intel` UI to lean into an “Eye of God” command-surface feel: minimal default UI, progressive reveal on activation, globe-first presentation, and dense diagnostics hidden until explicitly requested.
- Current `jongrayson/intel` UI direction to preserve: floating globe with transparent container, timeline controls directly under the globe, a thin cinematic top status strip instead of an explanatory hero card, and a `Systems Online` panel where the live number is the button that opens the activation/deactivation modal.
- System-layer UI pattern to preserve: layer options should be categorized by function (for example scoring, tracking, monitoring, filtering, analytics, recovery, controls, mapping), rendered as smaller squared tags, with active tags stronger and inactive tags muted green with black text.
- Globe interaction preferences to preserve: empty space around the globe should allow normal page scrolling, the globe should only respond when the pointer is over the sphere hit area, and globe auto-rotation should stop as soon as the user manipulates it, only resuming if they explicitly press a resume button.
- Globe visualization preference to preserve: mapped items should read as dots plus rings rather than raised pegs or pillars.
- Product framing decision: showing crime totals and danger-zone statistics is acceptable because the surface is positioned as a warning/awareness service, not as promotion or glamorization.
- Jon shared that his friend is the Pittsburgh Chief of Police and is interested in a tool like this, which makes Pittsburgh a strong pilot city and increases the value of building the zone-overlay + real-data workflow credibly.
- Pittsburgh map control styling was tightened for readability: map buttons should use transparent black backgrounds with white text, live in the top-left cluster, and keep the year selector last in the order.
- Pittsburgh map presentation decisions to preserve: map title text (`Map View · Pittsburgh, PA USA`) should switch to black in map mode, hotspot and zone hover affordances should use click-style pointer cursors, and the return control label should simply be `Globe`.
- Pittsburgh hotspot styling direction is now darker and heavier: hotspots should render as deeper, more opaque reds rather than light translucent heat.
- Pittsburgh police-zone visualization direction is now locked to fill-based polygons: no visible borders, each zone uses a different gray fill at roughly 50% transparency, hover shifts the zone fill toward red, and when zones are toggled off the labels remain while only the polygon fills hide.
- Pittsburgh map control copy is standardized to `Zones On` / `Zones Off`.
- `jongrayson/intel` now includes a live `Air` globe layer backed by public OpenSky in-air state data. It is controlled by an `Air` toggle and renders active flights as globe points over the city recommendation layer.
- `jongrayson/intel` now includes a live `Sat` globe layer backed by public CelesTrak TLE groups plus `satellite.js` propagation. It is controlled by a `Sat` toggle and clicking a satellite should surface name, network, orbit class, altitude, inclination, period, and NORAD/TLE details in the drawer.
